## Directory Purposes

**`lib/` (Git Submodule - v1.4.0):**
- Purpose: Shared Terraform modules and justfile utilities across all jacaranda services
- Contains: LXC module, base-infra module, vmid-ranges module, SSH host cert module; shared justfile utilities
- Key files: `lib/infrastructure/terraform/modules/lxc/main.tf`, `lib/infrastructure/just/terraform.just`
- Consumed by: `terraform/main.tf` (module "lxc"), `justfile` (import statements), env-specific Terraform files

**`terraform/` (Infrastructure Code):**
- Purpose: Define infrastructure-as-code using OpenTofu/Terraform
- Contains: Root module that calls LXC module; variables for instance config and infrastructure
- Key files: `terraform/main.tf` (LXC module invocation), `terraform/variables.tf` (input contracts)
- Env-specific overrides: `terraform/envs/test/main.tf` (single-node test config), `terraform/envs/prod/main.tf` (production template)
- Generated by: None (manually authored)
- Generated outputs: `ansible/inventory/test.yaml` (Ansible inventory), `terraform.tfstate`, `.terraform.lock.hcl`

**`ansible/` (Configuration Management):**
- Purpose: Configure LXC container after Terraform provisions it
- Contains: Playbooks and roles for Docker installation, SWAG/Twenty CRM deployment, health verification
- Key role: `ansible/roles/musa/` — single, idempotent role applied to all musa-group hosts
- Inventory: `ansible/inventory/test.yaml` auto-generated by Terraform; maps hosts → IPs and group memberships
- Templates rendered with: Secrets injected as extra-vars, non-secrets from `group_vars/all.yaml`, role defaults
- Generated outputs: Configuration files on LXC (docker-compose.yaml, .env, nginx configs)

**`scripts/` (Utility Scripts):**
- `op-read` — Bash helper to read 1Password items; used by justfile to inject secrets
- `op-connect.sh` — Set up 1Password Connect credentials in environment

**`terraform/envs/test/` (Test Environment Config):**
- Purpose: Instance and deployment settings for test environment
- Contains: Single instance definition (musa-test, VMID 1180, joseph node, 192.168.5.180)
- Calls: Parent `terraform/main.tf` module with test-specific instance map
- Key pattern: Base-infra module in local.base; VMID validation check; Proxmox provider config

**`terraform/envs/prod/` (Production Environment Placeholder):**
- Purpose: Production environment configuration (currently a template)
- Contains: Placeholder with base-infra module and similar structure to test
- Usage: Will define multi-node or HA setup when needed

**`ansible/roles/musa/tasks/` (Deployment Tasks):**
- Task execution order:
  1. Validate required variables (assert task)
  2. Install Docker prerequisites and Docker from official APT repo
  3. Authenticate to GHCR (Docker login with GitHub PAT)
  4. Create application directories (`/opt/musa`)
  5. Template configuration files (cloudflare.ini, docker-compose.yaml, .env, twenty.conf)
  6. Start Docker Compose stack
  7. Wait for SWAG and Twenty CRM health checks (retries with delays)

**`ansible/roles/musa/templates/` (Configuration Templates):**
- All templates use `{{ ansible_managed }}` header and Jinja2 variable substitution
- `docker-compose.yaml.j2` — 9-service definition; health checks; volume mounts; env variables
- `env.j2` — Twenty CRM environment file (loaded via `env_file:` in compose)
- `cloudflare.ini.j2` — Certbot DNS plugin config for Cloudflare API token
- `twenty.conf.j2` — Nginx reverse proxy to server:3000; websocket support; timeouts for CRM

## Key File Locations

**Entry Points:**
- `justfile` — Primary command interface (top-level recipes, module imports)
- `test.just` — Test environment recipes (`test::apply`, `test::deploy`, `test::full`, `test::validate`)
- `terraform/envs/test/main.tf` — Terraform entry point for test environment
- `ansible/playbooks/deploy.yaml` — Ansible entry point (applies musa role)

**Configuration:**
- `mise.toml` — Tool versions (just, opentofu, uv, pre-commit)
- `pyproject.toml` — Python environment (Ansible, toml, uv)
- `ansible/ansible.cfg` — Ansible behavior (pipelining, YAML output, no host key checking)
- `ansible/group_vars/all.yaml` — Shared Ansible variables (non-secrets)
- `ansible/roles/musa/defaults/main.yaml` — Role defaults (app_data_dir, timezone, versions)

**Core Logic:**
- `terraform/main.tf` — Root Terraform module; calls LXC module
- `terraform/variables.tf` — Input variable contracts
- `terraform/outputs.tf` — Outputs: instances, mgmt_ips, dns_entries, cname_entries, ansible_inventory_path
- `ansible/roles/musa/tasks/main.yaml` — Imperative task execution (Docker, config, start, verify)
- `ansible/roles/musa/handlers/main.yaml` — restart musa stack handler (docker compose up -d --force-recreate)

**Testing & Validation:**
- `test.just` — `verify` recipe (DNS/SSH checks), `validate` recipe (container health checks), `logs` recipe
- `ansible/roles/musa/tasks/main.yaml` — Health check tasks (SWAG port 80, Twenty /healthz endpoint)

## Naming Conventions

**Files:**
- Terraform: `*.tf` (main.tf, variables.tf, outputs.tf, encryption.tf)
- Ansible: `*.yaml` (playbooks, roles, templates use .j2 extension)
- Scripts: Lowercase, no extension (op-read, op-connect.sh)
- Justfile: `justfile`, `*.just`

**Directories:**
- Terraform: `terraform/`, `terraform/envs/{env}/`
- Ansible: `ansible/playbooks/`, `ansible/roles/{role}/`, `ansible/roles/{role}/{tasks,handlers,templates,defaults}/`
- Shared modules: `lib/infrastructure/terraform/modules/`, `lib/infrastructure/just/`

**Variables:**
- Terraform: Snake_case (e.g., `var.instances`, `local.base`, `var.ssh_public_key`)
- Ansible: Snake_case (e.g., `app_data_dir`, `cf_tunnel_token`, `pg_password`)
- Justfile: UPPER_SNAKE_CASE for constants and functions (e.g., `CYAN`, `GREEN`, `op_read`, `uv_run`)

**Resources & Locals:**
- Terraform modules: Lowercase (e.g., `module.lxc`, `module.base_infra`, `module.vmid`)
- Terraform outputs: Snake_case descriptive names (e.g., `instances`, `mgmt_ips`, `dns_entries`)
- Ansible groups: Lowercase, plural (e.g., `musa` group in inventory generated by LXC module)
- Ansible roles: Lowercase (e.g., `musa`)

**Environment Naming:**
- Test: `test` (single LXC, testing only)
- Production: `prod` (currently a template; will scale up)
- Directory structure: `terraform/envs/{test,prod}/`, `ansible/inventory/{test,prod}.yaml`

## Where to Add New Code

**New Infrastructure (VMs/LXCs):**
1. Define instance in `terraform/envs/{env}/main.tf` locals (e.g., new entry in `local.musa_instances`)
2. Update `terraform/variables.tf` if new variable types needed
3. Update outputs in `terraform/outputs.tf` if new outputs needed
4. Run `just test::init && just test::plan` to validate

**New Ansible Role:**
1. Create `ansible/roles/{new_role}/` with subdirs: `tasks/`, `handlers/`, `templates/`, `defaults/`
2. Create `ansible/roles/{new_role}/tasks/main.yaml` with task sequence
3. Create `ansible/roles/{new_role}/defaults/main.yaml` with defaults
4. Create playbook at `ansible/playbooks/{new_role}.yaml` that targets the role's group
5. Import/call playbook from main deploy.yaml or create separate justfile recipe

**New Service in Docker Compose Stack:**
1. Add service definition to `ansible/roles/musa/templates/docker-compose.yaml.j2`
2. Define healthcheck, depends_on, environment, volumes as needed
3. Add environment variables to `ansible/roles/musa/templates/env.j2` if needed
4. Add defaults to `ansible/roles/musa/defaults/main.yaml` if configurable
5. Update Ansible task validation in `ansible/roles/musa/tasks/main.yaml` if new secrets required
6. Update justfile validation recipes (`test::validate`, `test::logs`) if new container to check

**New Justfile Recipe:**
1. Add recipe to `test.just` (test environment) or `prod.just` (production)
2. Use shared utilities from `lib/infrastructure/just/` (terraform.just, ansible.just, secrets.just, styles.just)
3. Use color constants from `lib/infrastructure/just/styles.just` (CYAN, GREEN, RED, etc.)
4. Use `op_read` variable from `lib/infrastructure/just/secrets.just` for 1Password integration
5. Add documentation comment above recipe

**New Secrets (1Password Items):**
1. Create item in 1Password under `op://Homelab/{group}/{item_name}`
2. Add to justfile `check-secrets` recipe items list (update template for visibility)
3. Reference in Ansible task as `"{{ op_read }} 'op://Homelab/{group}/{item_name}'"`
4. Pass as extra-var to Ansible: `-e "var_name=$({{ op_read }} 'op://Homelab/...')"`
5. Consume in Jinja2 template: `{{ var_name }}`

## Special Directories

**`terraform/.terraform/` (Generated):**
- Purpose: Provider plugins and Terraform state metadata
- Generated: Yes (by `tofu init`)
- Committed: No (in .gitignore)

**`ansible/logs/` (Generated):**
- Purpose: Timestamped Ansible playbook execution logs
- Generated: Yes (by deploy recipe)
- Committed: No (in .gitignore)

**`terraform/terraform.tfstate*` (Generated):**
- Purpose: Infrastructure state (encrypted via 1Password Connect)
- Generated: Yes (by `tofu apply`)
- Committed: No (in .gitignore)
- Encryption: Via `.mise.local.toml` injecting 1Password Connect credentials

**`ansible/inventory/test.yaml` (Generated):**
- Purpose: Ansible inventory file auto-generated by Terraform LXC module
- Generated: Yes (by Terraform during apply, path specified in `ansible_inventory_path` module input)
- Committed: No (.gitkeep in inventory/ to preserve directory)
- Format: YAML with group definitions and host variables

**`/opt/musa/` (On LXC, created by Ansible):**
- Purpose: Application data directory on the running LXC
- Generated: Yes (by Ansible file task)
- Committed: No (resides on container filesystem)
- Contains: docker-compose.yaml, .env, cloudflare.ini, nginx/twenty.conf, backup/ and data volumes
