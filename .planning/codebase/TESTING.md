# Testing Patterns

**Analysis Date:** 2026-02-28

## Test Framework

**Runner:**
- Not applicable for this Infrastructure-as-Code repository
- Testing is performed via operational validation (health checks, connectivity tests)

**Assertion Library:**
- Ansible: `assert` module with `condition` and `fail_msg` fields
- Terraform: `check` blocks with `condition` assertions
- Shell: exit code validation via `set -e` and conditional operators

**Run Commands:**

```bash
# Pre-deployment validation
just check-secrets              # Verify 1Password items exist

# Health validation (post-deployment)
just test::validate             # Check service health
just test::logs                 # View container logs

# Infrastructure planning
just test::plan                 # Preview Terraform changes

# Full deployment with validation
just test::full                 # Create LXC + wait 30s + deploy + verify

# DNS and SSH connectivity check
just test::verify               # (private recipe - runs before validate)
```

## Test File Organization

**Location:**
- Health checks: embedded in Ansible tasks with `until` + `retries` + `delay`
- Validation recipes: `test.just` (module-based, not separate test directory)
- Preflight checks: separate private recipe `verify` in `test.just`
- Log aggregation: bash loop over container names in `logs` recipe

**Naming:**
- Ansible health checks: task name starting with "Wait for..." (example: "Wait for SWAG to respond", "Wait for Twenty CRM health check")
- Validation recipes: descriptive names (example: `verify`, `validate`, `logs`)
- Pre-commit validation: custom hooks in `lib/.lint/hooks/` (example: `validate-vmid-pattern.sh`)

**Structure:**

```
ansible/
├── playbooks/
│   └── deploy.yaml                 # Main playbook entry point
├── roles/musa/
│   ├── tasks/main.yaml             # Tasks including health checks
│   ├── handlers/main.yaml          # Handlers (restart stack)
│   ├── defaults/main.yaml          # Default variables
│   └── templates/                  # Configuration templates
├── group_vars/
│   └── all.yaml                    # Shared variables
└── inventory/
    └── test.yaml                   # Generated by Terraform (auto-created)

test.just
├── init                            # Initialize Terraform
├── plan                            # Plan infrastructure
├── apply                           # Create LXC container
├── deploy                          # Configure and start services
├── verify                          # Preflight (DNS, SSH)
├── validate                        # Health checks
├── logs                            # Container logs
└── full                            # Workflow: apply → wait → deploy
```

## Test Structure

**Suite Organization:**

Ansible playbooks use a single-role structure:

```yaml
# ansible/playbooks/deploy.yaml
- name: Deploy Musa (Twenty CRM)
  hosts: musa
  become: true
  roles:
    - musa
```

Task groups within `roles/musa/tasks/main.yaml` organized by section:

```yaml
- name: Validate required variables          # Validation block
  ansible.builtin.assert:
    that: [var1, var2, ...]
    fail_msg: "..."
  tags: [always]

- name: Install Docker prerequisites         # Setup block
  ansible.builtin.apt:
    name: [...]
  tags: [deploy]

- name: Deploy configuration templates       # Configuration block
  ansible.builtin.template:
    src: ...
    dest: ...
  notify: restart musa stack
  tags: [deploy]

- name: Start Docker Compose stack          # Startup block
  ansible.builtin.command:
    cmd: docker compose up -d
  tags: [deploy]

- name: Wait for SWAG to respond             # Health check block
  ansible.builtin.command:
    cmd: docker exec twenty-swag curl -sf ...
  register: swag_health
  until: swag_health.rc == 0
  retries: 30
  delay: 5
  tags: [verify]
```

**Patterns:**

**Setup Pattern:**
- Combine related apt/package installs into single `ansible.builtin.apt` task
- Create directories with `ansible.builtin.file` (use loop for multiple paths)
- Add credentials/keys with `ansible.builtin.command` and `stdin` (use `no_log: true`)
- All setup tasks tagged `[deploy]`

**Validation Pattern:**
- Use `ansible.builtin.assert` at start of playbook with `tags: [always]`
- Check variable presence and non-empty: `variable | length > 0`
- Include `success_msg` for clear feedback on passing validation

**Template Deployment Pattern:**
- Use `ansible.builtin.template` with src/dest
- Set mode (e.g., `0600` for secrets, `0644` for configs)
- Use `notify: restart musa stack` to trigger handler on change
- Use `no_log: true` for templates containing secrets
- Include `{{ ansible_managed }}` in first line of generated templates

**Health Check Pattern:**
- Use `register` to capture command output/exit code
- Use `until` + `retries` + `delay` for polling (example: 30 retries, 5s delay = 150s timeout)
- Use `changed_when: false` to avoid marking as "changed"
- Tag health checks with `[verify]` for selective execution
- Use `ansible.builtin.uri` for HTTP checks (example: Twenty CRM `/healthz` endpoint)
- Use `docker exec` for container-internal commands (example: SWAG curl test)

## Mocking

**Framework:** Not applicable (Infrastructure-as-Code, no unit testing framework)

**Approach for External Dependencies:**
- Docker Compose uses explicit service dependencies: `depends_on: { db: { condition: service_healthy } }`
- Ansible `until` loops wait for services to be healthy before proceeding
- Health checks use actual HTTP endpoints, not mocks
- Terraform uses real Proxmox API (mocking not practical for infra testing)

**What to Mock:**
- Not applicable — external services (PostgreSQL, Redis, Twenty CRM) are real containers in the Docker Compose stack

**What NOT to Mock:**
- Database connections — use real PostgreSQL in container
- API endpoints — use real Twenty CRM server health check
- Container startup — rely on Docker health checks and Ansible `until` loops

## Test Types

**Validation Tests (Pre-Deployment):**
- **Script:** `just check-secrets` in `justfile`
- **Purpose:** Verify all required 1Password items exist before deployment
- **Scope:** 7 items checked (secrets, API tokens, zone IDs)
- **Pattern:**
  ```bash
  items=(
      "Homelab/musa-project-crm-test/cf_tunnel_token"
      "Homelab/musa-project-crm-test/pg_password"
      ...
  )
  for item in "${items[@]}"; do
      if op_read "op://$item" > /dev/null 2>&1; then
          printf '  OK %s\n' "$item"
      else
          printf '  MISSING %s\n' "$item"
      fi
  done
  ```

**Infrastructure Tests (Terraform):**
- **Type:** `check` blocks in Terraform code
- **Example:** `check "vmid_allocation"` validates VMID ranges
- **Pattern:**
  ```hcl
  check "vmid_allocation" {
    assert {
      condition = alltrue([
        for name, inst in local.musa_instances :
        contains(module.vmid.validate.lxc, inst.vmid)
      ])
      error_message = "VMID outside LXC range (1001-1254)"
    }
  }
  ```

**Configuration Tests (Ansible Assertions):**
- **Type:** `ansible.builtin.assert` tasks at start of playbook
- **Purpose:** Validate required variables are defined and non-empty
- **Pattern:**
  ```yaml
  - name: Validate required variables
    ansible.builtin.assert:
      that:
        - cf_tunnel_token is defined
        - cf_tunnel_token | length > 0
      fail_msg: "Required variables must be set"
    tags: [always]
  ```

**Health Checks (Post-Deployment):**
- **Type:** Ansible `until` loops and `ansible.builtin.uri` module
- **Purpose:** Verify services are running and responding
- **Examples:**
  - SWAG HTTP port 80: `docker exec twenty-swag curl -sf http://localhost:80`
  - Twenty CRM `/healthz`: `ansible.builtin.uri: http://localhost:3000/healthz`
  - PostgreSQL readiness: `docker exec db pg_isready -U postgres`
  - Redis ping: `docker exec redis redis-cli ping`
- **Pattern (Polling):**
  ```yaml
  - name: Wait for SWAG to respond
    ansible.builtin.command:
      cmd: docker exec twenty-swag curl -sf ...
    register: swag_health
    until: swag_health.rc == 0
    retries: 30
    delay: 5
    changed_when: false
    tags: [verify]
  ```
- **Pattern (HTTP):**
  ```yaml
  - name: Wait for Twenty CRM health check
    ansible.builtin.uri:
      url: "http://localhost:3000/healthz"
    register: twenty_health
    until: twenty_health.status == 200
    retries: 30
    delay: 10
    tags: [verify]
  ```

**Preflight Tests:**
- **Script:** `verify` recipe in `test.just` (tagged `[private]`)
- **Purpose:** Check DNS and SSH connectivity before health checks
- **Tests:**
  - DNS: `dig +short {hostname}.lan`
  - SSH: `ssh -o ConnectTimeout=5 root@{hostname}.lan hostname`

**Linting and Validation:**
- **Tools:** pre-commit hooks (via `lib/.lint/pre-commit-config.yaml`)
- **Tests:**
  - YAML: `yamllint` with custom rules (line-length: 160, indentation: 2)
  - Shell: `shellcheck` (excludes `/templates/`)
  - Terraform: `terraform_fmt` (excludes `encryption.tf`)
  - Markdown: `markdownlint-cli2` (auto-fix)
  - Custom: `validate-vmid-pattern`, `validate-op-secrets`, `no-yml-extension`

## Common Patterns

**Async Task Pattern (Just):**

```bash
# Long-running operation with progress indicator
just test::apply       # Creates LXC (terraform apply)
@echo "Waiting 30s for LXC to be ready..."
@sleep 30
just test::deploy      # Configures services (ansible-playbook)
```

**Environment Variable Injection Pattern:**

```bash
# In test.just
deploy:
    #!/usr/bin/env bash
    export ANSIBLE_LOG_PATH="logs/ansible-$(date +%Y%m%d-%H%M%S).log"
    {{ uv_run }} ansible-playbook \
        {{ ansible_verbose }} \
        -i inventory/test.yaml \
        playbooks/deploy.yaml \
        -e "cf_tunnel_token=$({{ op_read }} 'op://...')" \
        -e "pg_password=$({{ op_read }} 'op://...')" \
        ...
```

**Error Handling Pattern (Shell):**

```bash
#!/bin/bash
set -euo pipefail

error() {
    echo "[ERROR] $*" >&2
    exit 1
}

debug() {
    if [[ "${DEBUG:-0}" == "1" ]]; then
        echo "[DEBUG] $*" >&2
    fi
}

# Function entry validation
check_token() {
    if [[ -z "${OP_CONNECT_TOKEN:-}" ]]; then
        error "OP_CONNECT_TOKEN environment variable is required"
    fi
}

# Retry with fallover
api_request() {
    local servers
    IFS=',' read -ra servers <<< "$OP_CONNECT_SERVERS"

    for server in "${servers[@]}"; do
        if result=$(curl -sf --max-time "$TIMEOUT" ...); then
            echo "$result"
            return 0
        fi
    done

    error "All servers unreachable"
}
```

**Polling Pattern (Ansible):**

```yaml
- name: Wait for service to be healthy
  ansible.builtin.command:
    cmd: some-health-check-command
  register: health_result
  until: health_result.rc == 0           # Exit code = 0
  retries: 30                            # Try 30 times
  delay: 5                               # Wait 5s between retries
  changed_when: false                    # Don't mark as "changed"
  tags: [verify]

- name: Wait for HTTP endpoint
  ansible.builtin.uri:
    url: "http://localhost:3000/healthz"
  register: http_result
  until: http_result.status == 200       # HTTP 200
  retries: 30
  delay: 10
  tags: [verify]
```

**Template Generation Pattern:**

```yaml
- name: Deploy configuration file
  ansible.builtin.template:
    src: config.yaml.j2                  # Jinja2 template
    dest: "{{ app_data_dir }}/config.yaml"
    mode: "0644"                         # Readable by service
  notify: restart musa stack             # Trigger handler on change
  no_log: true                           # Hide output if contains secrets
  tags: [deploy]
```

**Conditional Execution Pattern (Just):**

```just
# Destructive operation requires confirmation
[confirm("Destroy Musa test LXC container? This is DANGEROUS!")]
destroy: (tf-destroy "test")

# Selective tag-based execution
ansible_verbose := if env_var("VERBOSE", "") == "1" { "-vv" } else { "" }
debug_flag := if env_var("DEBUG", "") == "1" { "--debug" } else { "" }
```

## Pre-Deployment Checklist

Before running `just test::full`:

```bash
# 1. Initialize tools
mise trust && mise install
uv sync

# 2. Verify secrets exist
just check-secrets

# 3. Initialize Terraform
just test::init

# 4. Plan infrastructure
just test::plan

# 5. Review plan output and approve
```

## Post-Deployment Validation

After running `just test::full`:

```bash
# 1. Check DNS resolution
dig +short musa-test.lan

# 2. Verify SSH access
ssh root@musa-test.lan hostname

# 3. Check all containers running
ssh root@musa-test.lan docker ps

# 4. Verify service health
just test::validate

# 5. Review logs if issues
just test::logs
```
